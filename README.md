# Локальный чат с LM Studio

Python 3.11+, FastAPI, статический интерфейс без сборки, локальная SQLite. История чатов хранится приложением на диске и не зависит от истории LM Studio. Облачные сервисы не используются.

## Запуск

1. Установите [LM Studio](https://lmstudio.ai/), загрузите **чатовую** модель (не embedding-модель), откройте вкладку **Developer / Local Server** и запустите локальный сервер. В настройках сервера убедитесь, что он слушает `127.0.0.1:1234`; проверьте `curl http://127.0.0.1:1234/v1/models`. Загруженная чатовая модель должна присутствовать в списке.
2. В каталоге проекта выполните:

   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

3. Откройте http://127.0.0.1:8000/. Выберите чат-модель, создайте чат и отправьте сообщение: название чата автоматически станет текстом первого сообщения пользователя (даже если модель не ответила). Последующие сообщения название не меняют; при необходимости чат можно переименовать вручную. В другой вкладке можно проверить `http://127.0.0.1:8000/api/health`. После перезапуска приложения откройте сохранённый чат — история и название остаются в SQLite.

Пример локальных параметров (перед `uvicorn`):

```sh
export LM_STUDIO_BASE_URL=http://127.0.0.1:1234/v1
export CHAT_DB_PATH=./chat.sqlite3
```

Адрес LM Studio можно изменить, если сервер работает на другом локальном адресе. По умолчанию база создаётся в `chats.sqlite3` в каталоге проекта, независимо от текущего рабочего каталога. Приложение по умолчанию слушает только `127.0.0.1`; не публикуйте сервер без отдельной настройки доступа. Базу данных регулярно копируйте как обычный локальный файл после остановки приложения.

## Ограничения контекста и метрики

Сообщение ограничено 8000 символами; в контекст модели помещаются последние сообщения чата суммарно до 32000 символов. Старые сообщения при превышении лимита не отправляются модели, но остаются в SQLite и отображаются в интерфейсе. Обрезка определяется длиной текста, а не реальным контекстным окном выбранной модели; при меньшем окне модель может вернуть ошибку. Время ответа и время до первого фрагмента измеряются сервером; токены берутся только из `usage` LM Studio. Если `usage` отсутствует, отображается «н/д». Прерванный или ошибочный ответ хранится отдельно от завершённого и помечен соответствующим статусом.

## Проверки

```sh
pytest -q
```

Проверка с настоящей чатовой моделью: создайте чат и задайте два связанных вопроса, например «Запомни кодовое слово: кедр» и «Какое кодовое слово?». Убедитесь, что второй ответ учитывает историю; текст первого ответа появляется постепенно, после окончания видны длительность, входные/выходные токены (или «н/д» при отсутствии `usage`) и идентификатор модели. Перезапустите приложение: сообщения и метрики остаются. Остановите сервер LM Studio: чаты продолжают открываться, а попытка генерации показывает ошибку; запустите его снова и обновите модели.
