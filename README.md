# Локальный RAG на LM Studio

Учебное приложение: извлечение текста из файлов, два способа разбиения, локальные FAISS + SQLite, сравнение поиска и чат с RAG или без него. Ни эмбеддинги, ни запросы чата не отправляются в облачный API: используется только указанный локальный сервер LM Studio. Для PDF выполняется извлечение текстового слоя PyMuPDF; OCR сканов не предусмотрен.

## Установка и запуск

Нужны Python 3.11+, LM Studio с включённым локальным сервером OpenAI-compatible API и две загруженные модели: chat и embedding. Рекомендуемые проверенные ID: `qwen/qwen3.5-9b` и `text-embedding-nomic-embed-text-v1.5`. В LM Studio включите Local Server на `http://127.0.0.1:1234/v1`, загрузите обе модели, затем в корне проекта:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Откройте адрес, указанный Streamlit (обычно `http://localhost:8501`). На боковой панели нажмите «Получить список моделей», выберите точные ID моделей (или введите их вручную). На вкладке «Документы и индексация» выберите демонстрационный корпус либо загрузите несколько файлов и нажмите «Индексировать обеими стратегиями». Просмотрите метрики и чанки, на вкладке «Сравнение стратегий» задайте вопрос и запустите `Hit@5`, затем на вкладке «Чат» создайте диалог и переключайте «С RAG / Без RAG». Диалоги и индексы находятся в `data/`, переживают перезапуск Streamlit. Для смены embedding-модели нужна новая индексация. Без запущенного LM Studio можно просматривать документы и ранее сохранённую историю, но эмбеддинги, поиск и чат недоступны.

Новый диалог сначала называется «Новый диалог». После сохранения первого ответа названием становится первое сообщение пользователя; последующие сообщения его не меняют.

При повторной индексации новая пара файлов FAISS и записи SQLite публикуются как единая версия. Поиск использует только активную версию; предыдущие снимки остаются в `data/` как история и занимают место на диске. Для полного сброса локальных данных остановите приложение и удалите каталог `data/` целиком — это также удалит диалоги.

## Форматы и ограничения

Принимаются `.md`, `.markdown`, `.txt`, `.py`, `.pdf`, `.rst`, `.json`, `.yaml`, `.yml`, `.toml`, `.js`, `.ts`, `.css`, `.html`, `.csv`; максимум 10 МиБ на файл. Пустой и бинарный текст отклоняется. Для PDF сохраняются номера страниц: пустые страницы в частично текстовом PDF отмечаются предупреждением, полностью сканированный PDF — ошибкой; OCR нет. Загруженные имена файлов используются как подписи/идентификаторы, не как путь сохранения. Ограничение контекста и число последних сообщений в запросе защищают окно модели, но итоговая длина ответа зависит от выбранной модели.

## Демонстрационные данные

В `corpus/` находятся девять оригинальных тематических Markdown-документов о вымышленном сервисе «Контур»: **11 145 слов, 22,29 условной страницы** по правилу 500 слов/страница; PDF в корпусе нет. `corpus/questions.json` содержит 18 контрольных вопросов с ожидаемыми файлами и разделами. Методика подсчёта и разбивка по документам — в `corpus/README.md`.

На локальном сервере LM Studio с embedding-моделью `text-embedding-nomic-embed-text-v1.5` (размерность 768) и параметрами 1000/150 получен следующий воспроизводимый снимок; времена зависят от оборудования:

| Стратегия | Чанков | Средний / медианный размер, символов | Построение, с | Hit@5 на 18 вопросах |
| --- | ---: | ---: | ---: | ---: |
| fixed | 108 | 944,95 / 995 | 20,60 | 11/18 (61,1%) |
| structural | 164 | 598,18 / 602 | 19,29 | 13/18 (72,2%) |

## Повторяемая проверка

```sh
source .venv/bin/activate
python -m pytest -q
```

`Hit@5` проверяет присутствие ожидаемого файла среди пяти найденных чанков, а не достоверность ответа языковой модели. Ожидаемые разделы показаны для ручной проверки и не входят в эту метрику: фиксированные чанки могут пересекать заголовки. Используются косинусные оценки нормализованных эмбеддингов; числа и качество различаются при смене embedding-модели.

Проверено локально: **12 тестов** (`python -m pytest -q`), живые `/models`, `/embeddings` и потоковый `/chat/completions`, индексация корпуса через интерфейс, сравнение, оба режима чата, повторное открытие и продолжение диалога после перезапуска Streamlit. Сканированный PDF без текстового слоя отображает ошибку и фактическое число страниц. `.streamlit/config.toml` ограничивает загрузку 10 МиБ на файл и привязывает веб-сервер к `127.0.0.1`.
