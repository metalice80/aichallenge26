# Оптимизация локальной LLM

Локальное однопользовательское веб-приложение: чат с LM Studio, профили и воспроизводимое сравнение профилей на одинаковых текстовых вопросах. Python 3.11+, FastAPI, SQLite. Никакие облачные модели, внешние API и CDN при работе не используются.

## Запуск

1. Установите **LM Studio 0.4.0+**, скачайте текстовую модель и включите локальный API-сервер на `127.0.0.1:1234` в разделе Developer. API должен отвечать на `GET /api/v1/models`. Приложение загружает выбранную модель с нужным контекстом по её базовому `key`, вручную загружать её не нужно.
2. В каталоге проекта:

   ```sh
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
   cp .env.example .env
   .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

3. Откройте `http://127.0.0.1:8000`. На первом успешном запросе списка моделей добавляются два редактируемых примера «Python · базовый» и «Python · кандидат оптимизации» для первой установленной текстовой модели. Оба являются **примерами**, их качество заранее неизвестно.

`.env` необязателен. `LM_STUDIO_URL` задаёт только сервер LM Studio (по умолчанию `http://127.0.0.1:1234`), `DATABASE_PATH` задаёт SQLite (по умолчанию `data/app.db`). Переменные окружения процесса имеют приоритет над `.env`. Для пробы без изменения имеющейся истории задайте `DATABASE_PATH=/tmp/llm-experiment.db`. Интерфейс не принимает адрес стороннего сервера. Откройте сайт только локально, без публикации порта 8000 наружу: авторизации нет.

Если в `data/app.db` хранится история предыдущего приложения, при первом открытии новая схема сохраняет старые таблицы и копирует `conversations`/`messages` в `chats`/`messages` (статус `legacy`); поля прежних метрик неизвестны и не выдумываются. Создайте резервную копию SQLite перед сменой версии, если база важна.

## Работа

- **Чат:** создайте чат, выберите сохранённый профиль, отправьте сообщение. Сервер отправляет каждый новый текстовый фрагмент по мере получения; база содержит полную историю, из неё каждый раз собирается контекст. Переименование/удаление чата доступно в разделе чата. Статус, время загрузки, время генерации, время первого фрагмента, токены и настройки сохраняются с ответом. При отключённом LM Studio доступ к сохранённым чатам/отчётам сохраняется.
- **Профили:** выберите установленную модель и (если имеются) вариант квантования. Интерфейс показывает размер и квантование только для варианта, выбранного в LM Studio; метаданные других вариантов не выдаются за его размер. При смене `context_length` модель выгружается/загружается через API по базовому ключу, затем фактическая конфигурация проверяется по `load_config` и `loaded_instances`. Варианты, не установленные в LM Studio, выбрать нельзя. Если профиль указывает не на выбранный в LM Studio вариант, генерация остановится с объяснением, не используя другой вариант. Температура 0–2, лимит ответа 1–32768, контекст 256–1048576 с дополнительным ограничением самой модели. Для исключения конкурирующих смен контекста генерации и опыты выполняются последовательно.
- **Сравнение:** создайте набор текстовых вопросов с необязательными критериями/эталонными фактами, выберите базовый и кандидатный профили, число повторов (3 по умолчанию), запустите опыт. Для каждого профиля проводится один прогрев (без учёта в агрегате); далее каждый вопрос в каждом повторе подаётся в отдельной чистой сессии (system prompt + вопрос). Измерения выполняются последовательно. Оцените точность, полноту и соблюдение формата каждого завершённого ответа от 1 до 5. Отчёт Markdown скачивается из экрана сравнения, включает текст вопросов и ответов, сырые метрики, снимки параметров и методику.

Если LM Studio завершил поток с `finish_reason=length`, ответ помечается как **неполный** и не участвует в истории для последующих запросов или в средних оценках. Полученные фрагменты, `usage` и причина сохраняются. Когда `completion_tokens` достигает `max_tokens`, увеличьте `max_tokens` в профиле и повторите запрос; иначе проверьте также `context_length` и размер вопроса. Изменение профиля не меняет параметры старого ответа. В опыте неполный прогрев или измерение прерывает запуск, чтобы обрезанный ответ не попал в агрегат.

### Ограничение выбора квантования LM Studio

`GET /api/v1/models` показывает `variants` и `selected_variant`, но [POST /api/v1/models/load](https://lmstudio.ai/docs/developer/rest/load) принимает базовый `key` и загружает выбранный в LM Studio вариант. Суффикс `@q4_k_m` в поле `model` на затронутых версиях возвращает `model_not_found`; [ограничение отслеживается разработчиками LM Studio](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/1462). REST API не предоставляет переключения варианта. Для чата выберите нужное квантование в интерфейсе LM Studio **до** отправки: приложение сверит выбор и откажется подменять вариант молча. При нескольких установленных вариантах модель перед ответом перезагружается, потому что список загруженных экземпляров не содержит идентификатор квантования.

Для **автоматического** сравнения Q4 и Q8 без вмешательства посреди опыта импортируйте уже установленные файлы как отдельные модели с разными ключами (`lms import /путь/модель-Q4.gguf --user-repo local/python-q4 --hard-link -y`, аналогично для Q8), убедитесь через `GET /api/v1/models`, что ключи различаются и относятся к одной базовой модели, затем укажите их в двух профилях. Команда [`lms import`](https://lmstudio.ai/docs/cli/local-models/import) с `--hard-link` не переносит исходный файл (файлы должны быть на одном томе). Без отдельных ключей попытка одного запуска с разными вариантами одной модели отклоняется **до** измерений. Это ограничение LM Studio, не доказательство равенства вариантов.


### Интерпретация метрик

- `total_seconds`: монотонное время Python от начала запроса генерации до конца потока. `first_token_seconds`: до первого **текстового** фрагмента. `load_seconds` измеряется отдельно и не входит во время генерации; ноль означает уже загруженную модель. Для времени и скорости итогом служит медиана успешных измеряемых повторов.
- Токены — только поля `usage.prompt_tokens` и `usage.completion_tokens` LM Studio; при их отсутствии «н/д», не приблизительный подсчёт слов. `tokens_per_second = completion_tokens / total_seconds` только при наличии выходных токенов и положительного времени. Прогрев из агрегата исключён. Сравнивайте одинаковое оборудование и фоновые условия.
- `ram_after_bytes` и `ram_peak_bytes`: при возможности сумма RSS процесса LM Studio и дочерних процессов, считанная через `psutil`, после загрузки и пик во время ответа. Учитываются только локальные процессы, среди которых найден слушатель порта указанного `LM_STUDIO_URL`; при другом сервере или невозможности привязать порт к PID значение «н/д» с причиной. Сохраняется источник с PID/именами. Это **расход процессов**, включая накладные расходы LM Studio, не память одной конкретной модели и не общая RAM компьютера. `model_size_bytes` — размер установленного файла из метаданных LM Studio, не измерение RAM. GPU/VRAM не измеряются: надёжный переносимый источник не подключён; на macOS unified memory не следует выдавать за отдельную VRAM.
- Оценки выставляет человек; среднее считается только среди полностью оценённых успешных ответов, рядом показывается число оценок. Сравнение базового профиля и кандидата не предполагает, что второй всегда лучше.

## Проверки

```sh
.venv/bin/python -m pytest -q
```

Тесты с подменённым локальным API покрывают поток, историю после нового открытия базы, неизменяемые снимки, отсутствие `usage`, обрыв потока, загрузку по базовому ключу при смене контекста, безопасный отказ для невыбранного варианта, прогрев, последовательное сравнение, ручные оценки и отчёт. Можно проверить вручную без работающей модели: остановите LM Studio, откройте страницу и убедитесь, что старые чаты и отчёты доступны, а список моделей показывает сообщение об ошибке. Для проверки реальной модели: убедитесь, что `/api/v1/models` показывает LLM; создайте два профиля с одной моделью, но разной температурой/максимумом токенов и допустимым контекстом; задайте один вопрос, получите поток и токены, перезапустите веб-сервер и откройте тот же чат; затем выполните опыт с одним вопросом и 1–3 повторами, оцените ответы и скачайте отчёт. Для сравнения квантований следуйте инструкции выше. Ошибки нехватки RAM/контекста зависят от локальной модели и не эмулируются автоматически.
