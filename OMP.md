# Задание для Oh My Python (OMP): локальный веб-чат с LM Studio

Создай работающее Python-приложение с веб-интерфейсом для общения с локальной LLM через LM Studio. Результат должен запускаться на одном компьютере без облачных моделей и сохранять историю чатов между перезапусками.

Выполни реализацию в текущем проекте. Этот файл — задание на разработку, поэтому заверши работу запускаемым приложением и проверками, а не только планом или описанием архитектуры.

## Цель и рамки

- Один локальный пользователь, текстовые диалоги.
- Backend: Python 3.11+ и FastAPI.
- Frontend: HTML, CSS и JavaScript без обязательной сборки Node.js.
- Хранилище: SQLite в локальном файле.
- Модель: локальный сервер LM Studio. Адрес по умолчанию — `http://127.0.0.1:1234/v1`; его можно изменить через переменную окружения `LM_STUDIO_BASE_URL`.
- Запрещены вызовы облачных LLM и зависимость от внешних API для работы чата.

## Архитектура

```text
Браузер ──HTTP/SSE──> FastAPI ──HTTP──> LM Studio ──> локальная LLM
                         │
                         └───────────> SQLite
```

Раздели код на веб-маршруты, сервис диалогов, клиент LM Studio и слой хранения. Сохраняй историю в SQLite как основной источник данных. Для каждого запроса формируй массив сообщений выбранного чата и отправляй его на `POST /v1/chat/completions`. Для списка доступных моделей используй `GET /v1/models`. Не полагайся на внутреннюю историю LM Studio: пользователь должен видеть и продолжать сохранённые чаты после перезапуска приложения.

## Функции интерфейса

1. Создать чат, открыть существующий чат, переименовать и удалить его.
2. Отправить текстовое сообщение и видеть ответ модели по мере генерации.
3. При открытии чата видеть всю сохранённую переписку в правильном порядке.
4. Выбрать доступную модель; отображать модель, использованную для каждого ответа.
5. Под каждым ответом показывать общее время ответа, число входных и выходных токенов. Если доступны данные, дополнительно показывать время до первого фрагмента ответа.
6. Показывать понятное состояние при выключенном сервере LM Studio, отсутствии модели, ошибке генерации и прерванном потоке. Не выдавать частичный ответ за завершённый.

Интерфейс должен быть удобен на настольном экране и телефоне. Сообщения модели выводи безопасно: не вставляй необработанный текст модели через `innerHTML`.

## Работа с моделью и метрики

- Запрашивай потоковый ответ (`stream: true`) и передавай `stream_options: {"include_usage": true}`. Передавай фрагменты текста браузеру, затем завершающее событие с метриками.
- Измеряй полное время ответа на сервере монотонными часами: от начала вызова LM Studio до завершения потока. Время до первого текстового фрагмента измеряй отдельно.
- Число токенов бери из `usage.prompt_tokens` и `usage.completion_tokens` в ответе LM Studio. Если установленная версия LM Studio не прислала эти данные, сохраняй `NULL` и показывай «н/д»; не подменяй реальные токены числом слов или символов.
- Для каждого ответа сохраняй идентификатор модели и статус: `completed`, `failed` или `interrupted`.
- Предусмотри ограничение длины входного сообщения и размера отправляемой истории. При достижении лимита контекста явно сообщай об этом пользователю или применяй документированную политику обрезки старых сообщений.
- Задай разумный тайм-аут соединения и длительный тайм-аут чтения для генерации. Ошибки LM Studio обрабатывай без потери уже сохранённой истории.

## Данные

Минимальная схема:

- `chats`: `id`, `title`, `model_id`, `created_at`, `updated_at`.
- `messages`: `id`, `chat_id`, `role`, `content`, `status`, `model_id`, `created_at`, `duration_ms`, `time_to_first_token_ms`, `prompt_tokens`, `completion_tokens`.

Токены и время относятся к конкретному ответу ассистента. Суммарную статистику чата при необходимости вычисляй из его завершённых ответов. Обеспечь связь сообщений с чатом и сортировку по времени/идентификатору.

## Ожидаемые HTTP-маршруты

Конкретные имена можно уточнить в реализации, сохранив функции:

| Маршрут | Назначение |
| --- | --- |
| `GET /` | Веб-интерфейс |
| `GET /api/health` | Состояние приложения и соединения с LM Studio |
| `GET /api/models` | Список локальных моделей |
| `GET /api/chats` / `POST /api/chats` | Список и создание чатов |
| `GET /api/chats/{id}` / `PATCH /api/chats/{id}` / `DELETE /api/chats/{id}` | Просмотр, переименование и удаление |
| `POST /api/chats/{id}/messages/stream` | Отправка сообщения и поток ответа |

Для последнего маршрута браузер может читать поток ответа через `fetch` и `ReadableStream`, поскольку сообщение отправляется методом POST. Формат событий должен явно различать текст, финальные метрики и ошибку.

## Результат работы

Создай исходный код, файл зависимостей и `README.md` с командами установки и запуска. В README объясни, как запустить локальный сервер LM Studio, загрузить модель, проверить адрес сервера и открыть веб-интерфейс. Добавь пример переменных окружения. Приложение по умолчанию должно слушать `127.0.0.1`.

## Проверка готовности

Проверь автоматическими тестами работу хранилища, маршрутов чатов и обработку потока с подменённым локальным ответом LM Studio. Затем проверь вручную или опиши воспроизводимую проверку с настоящей моделью:

1. Создать чат и отправить два связанных вопроса: второй ответ учитывает первый.
2. Увидеть поток ответа, время и токены.
3. Перезапустить приложение: чат, сообщения и метрики сохранились.
4. Выключить LM Studio: интерфейс показывает ошибку, сохранённые чаты доступны.
5. Проверить, что конфигурация и код не содержат адресов облачных моделей.

Заверши работу кратким отчётом: что создано, как запустить, какие проверки прошли и какие ограничения остались.
